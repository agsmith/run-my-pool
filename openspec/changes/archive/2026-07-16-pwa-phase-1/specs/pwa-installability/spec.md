## ADDED Requirements

### Requirement: App has a valid web app manifest
The system SHALL serve a `manifest.json` from the root that meets browser installability criteria: `name`, `short_name`, `start_url`, `display: standalone`, `theme_color`, `background_color`, and at least one icon at 192px and one at 512px.

#### Scenario: Manifest is present and valid
- **WHEN** a browser requests `/manifest.json`
- **THEN** the server returns a valid JSON document with all required PWA manifest fields

#### Scenario: Manifest is linked in the HTML document
- **WHEN** any page is loaded
- **THEN** the `<head>` contains `<link rel="manifest" href="/manifest.json">`

---

### Requirement: App icons are available at required sizes
The system SHALL provide PNG app icons at 192×192 and 512×512 pixels, plus a maskable 512×512 variant for Android adaptive icon support.

#### Scenario: Icons resolve at expected paths
- **WHEN** a browser or manifest references `/icons/icon-192x192.png`, `/icons/icon-512x512.png`, or `/icons/icon-512x512-maskable.png`
- **THEN** each path returns a valid PNG image at the correct dimensions

---

### Requirement: Service worker is registered
The system SHALL register a service worker on page load. The service worker MUST be generated by `next-pwa` and served at `/sw.js`.

#### Scenario: Service worker registers successfully
- **WHEN** the app is loaded in a browser that supports service workers
- **THEN** `navigator.serviceWorker.controller` is set after the first page load

#### Scenario: Service worker is disabled in development
- **WHEN** the app runs with `NODE_ENV=development`
- **THEN** no service worker is registered

---

### Requirement: Offline fallback page is served
The system SHALL display a static offline page when a navigation request fails due to network unavailability.

#### Scenario: Offline page shown when network is unavailable
- **WHEN** a user attempts to navigate to any page while offline
- **THEN** the app displays the `/offline` page with a "Try Again" button

#### Scenario: Reload button triggers page refresh
- **WHEN** a user clicks "Try Again" on the offline page
- **THEN** the browser attempts to reload the current page

---

### Requirement: App launches in standalone mode from home screen
The system SHALL display without browser navigation chrome when launched from a home screen shortcut.

#### Scenario: Standalone display on Android
- **WHEN** a user installs the app via Chrome on Android and launches it from the home screen
- **THEN** the app opens without the browser address bar or navigation buttons

#### Scenario: Standalone display on iOS
- **WHEN** a user adds the app to their iOS home screen via Safari and launches it
- **THEN** the app opens in full-screen mode without the Safari UI

---

### Requirement: Generated service worker files are excluded from version control
The system SHALL exclude `public/sw.js` and `public/workbox-*.js` from git, as these are build artifacts generated by `next-pwa`.

#### Scenario: Gitignore covers generated files
- **WHEN** a build is run and `sw.js` and `workbox-*.js` are generated into `public/`
- **THEN** `git status` does not list these files as untracked
